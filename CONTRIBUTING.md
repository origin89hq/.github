# Contributing to Origin89

Follow the [engineering standards](https://github.com/origin89hq/engineering)
for working practices, tests, writing, branches, commits, and PRs. Read the target
repository's `AGENTS.md` and contribution guide for its commands and constraints.

Track confirmed problems left outside the current fix using the
[shared issue rule](https://github.com/origin89hq/engineering/blob/main/skills/origin89-working/SKILL.md#track-unfinished-work).
Use `gh` to find or create the issue, verify it, and return its URL.

Keep PRs focused. Explain the problem, resulting behavior, and checks actually
run. Use short conventional commit and PR titles without assistant attribution.
Write each PR-body paragraph on one physical line.

Keep private RFCs and research in `internal-research`. Report vulnerabilities
through the [security policy](SECURITY.md), with redacted evidence.

For shared instruction and skill adoption, follow the
[adoption guide](https://github.com/origin89hq/engineering/blob/main/docs/adopting.md).
Engineering maintains shared skill content; adopting repositories refresh it at
the next task. Install native assistant instruction files in each consumer.
